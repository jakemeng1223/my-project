# 给 Gemini 的提示词：设计"每周复盘"页面

> 用法：把下面分隔线之间的内容整段复制给 Gemini。它会输出一个完整的 `review.html`。
> 拿到后放进 `src/main/resources/static/`（可以改名为 `review-gemini.html`，和 Claude 版并存），启动项目后打开 `http://localhost:8080/review-gemini.html` 对比。

---

你是一名资深前端设计师兼工程师。请为我的个人项目"人生数据库"设计并实现一个**每周复盘**页面，输出**一个完整、可直接运行的 HTML 文件**（HTML + CSS + 原生 JavaScript 写在同一个文件里，不用任何框架、不引用任何外部 CDN、字体或图片）。

## 项目背景
- 这是一个 Spring Boot 后端 + 静态页面的项目，用来记录我每天的睡眠、情绪、开销和做了什么。
- 我是一名大四学生，目标是改掉熬夜（现在常常凌晨 2～5 点才睡），目标入睡时间是 **23:30**。
- 现有两个页面：日记（`/`）和全面发展矩阵（`/matrix.html`）。新页面路径是 `/review.html`。
- 页面在**电脑和手机浏览器**上都要好用（手机宽度 360～430px），并支持**深色模式**（`prefers-color-scheme: dark`）。

## 后端接口（只读，不需要改后端）
`GET /api/records` 返回全部每日记录（JSON 数组，按日期倒序），每条形如：

```json
{
  "id": 12,
  "recordDate": "2026-11-03",
  "sleepTime": "01:52:00",
  "wakeTime": "13:11:00",
  "mood": 8,
  "spending": 95.00,
  "meals": "火锅",
  "activities": "睡前不看手机；开通健康数据自动同步",
  "note": "",
  "createdAt": "2026-11-03T14:00:00",
  "updatedAt": "2026-11-03T14:00:00"
}
```

字段说明：
- `recordDate`：日期，`YYYY-MM-DD`，每天最多一条
- `sleepTime` / `wakeTime`：入睡 / 起床时间，`HH:mm:ss` 或 `HH:mm`，可能为 `null`。入睡常在凌晨，比如 `03:10` 睡、`11:00` 起；也可能 `23:40` 睡、`08:00` 起（跨午夜）
- `mood`：情绪 1～10 分，可能为 `null`
- `spending`：当天开销（元），数字，可能为 `null`
- `meals` / `activities` / `note`：文本，可能为空

## 页面要做什么
目标：**一周看一次，看完知道下周只改哪一件事。**

1. **周切换**：按周一到周日分周，默认显示本周；可以切到上一周 / 下一周（不能超过本周）；网址带上 `?week=YYYY-MM-DD`（那周的周一），刷新后停在同一周。
2. **一句话总结**：页面最显眼的位置，用一句人话总结本周，比如"这周记了 5 天，平均 02:40 入睡，比上周早 20 分钟，情绪 6.4 分"。
3. **核心指标 + 和上周对比**：记录天数（x/7）、平均入睡时间、平均睡眠时长、平均情绪、本周开销合计。每个指标显示比上周变好还是变差，不能只靠颜色区分，要有箭头或文字。
   - ⚠️ 平均入睡时间要正确处理跨午夜：23:00 和 01:00 的平均应该是 00:00，不是 12:00。
4. **七个夜晚**：本周每天的睡眠时段可视化（能一眼看出几点睡、几点醒、睡了多久），标出 23:30 目标线；凌晨 3 点以后才睡的要醒目标出；没记录的天要和"有记录"明显区分。
5. **情绪走势**：最近 8 周每周情绪平均分的走势图，缺数据的周要断开、不能硬连；鼠标悬停 / 手指点击时显示具体数值。
6. **开销**：本周每天花了多少钱，标出花得最多的那天，显示合计和日均；悬停显示当天吃了什么（`meals`）。
7. **本周发现**：根据数据自动生成 3～5 条中文观察，比如最晚 / 最早入睡是哪天、情绪最好那天做了什么（引用 `activities`）、哪几天没记录、开销比上周多 / 少了多少。
8. **复制给 AI**：一个按钮，把本周 7 天的数据整理成 Markdown 表格（日期、入睡、起床、时长、情绪、开销、吃了什么、做了什么、备注）加一行汇总，复制到剪贴板，方便我粘贴给 AI 做周报。注意在局域网 `http://` 访问时 `navigator.clipboard` 可能不可用，要有降级方案。
9. **导航**：页头右侧有导航，三个链接：日记 `/`、复盘 `/review.html`（当前页高亮）、矩阵 `/matrix.html`。

## 质量要求
- 所有图表用内联 SVG 或 HTML/CSS 自己画，不要引入图表库。
- 数据为空（新用户 / 某周没记录 / 接口失败）时，每一块都要有友好的空状态，不能报错或出现 `NaN`、`undefined`。
- 用户输入的文本（`meals`、`activities`、`note`）插入页面时要防 XSS（转义，或用 `textContent`）。
- 手机上不能出现横向滚动条；字号在手机上不小于 11px。
- 中文界面，文案口语化、简短。
- 代码里写简短的中文注释，说明关键逻辑（比如跨午夜怎么算）。

## 设计方向（你来发挥）
- 风格自定，但要有辨识度，不要千篇一律的"后台管理模板"。可以参考：纸质手账、报纸版面、终端风格、日式极简、数据新闻……选一个方向，贯彻到底。
- 颜色要克制：一个主色 + 中性色，状态色（好 / 差）只用于升降对比。
- 浅色和深色模式各自调好颜色，不要简单反色。

## 输出
1. 先用 3～5 句话说明你选择的设计方向和理由。
2. 然后给出完整的 `review.html` 代码（一个代码块，从 `<!doctype html>` 开始）。
